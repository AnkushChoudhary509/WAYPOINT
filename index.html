What it does

Three things, done well

Waypoint isn't another CI dashboard. It's the one guardrail that acts on your behalf when a deploy goes sideways.

Automatic rollback

Set thresholds on error rate, latency, or a custom metric. Cross the line, and Waypoint reverts the deploy before a human opens Slack.

Canary by default

Every deploy ships to a small slice of traffic first. Waypoint watches it in real time before letting it near everyone else.

Works with what you have

Drop into GitHub Actions, GitLab CI, or a raw webhook. No new infrastructure to stand up or maintain.

How it works

Three steps, in order

Nothing to migrate. Waypoint sits alongside your existing pipeline and only speaks up when it needs to.

01

Connect your pipeline

Point Waypoint at your existing CI/CD. We don't replace it — we watch what it ships.

02

Set your guardrails

Define what "bad" looks like: error rate, p99 latency, or a metric you already track.

03

Deploy like normal

Waypoint watches quietly in the background and only acts — by reverting — when something's actually wrong.

We built this after a bad Tuesday

One deploy turned into a 40-minute outage because nobody happened to be looking at the dashboard when the error rate spiked. Waypoint exists so that "nobody was watching" stops being how outages start.
